# 8.23 Computational Diagnostics of Return

As in Closure, an external simulation may use mathematics richer than the ontology it tests. Counting iterations, measuring graph properties or assigning ensemble statistics is permissible as diagnostic instrumentation. As a result, long as those quantities are not silently promoted into primitives of the modeled world. A computational implementation should test at least the following.

Anchor independence. Is F specified before observing which trajectories recur?

Nontrivial departure. Does the candidate trajectory actually leave Dom<sub>F</sub>?

Re-entry. Does a resultant state satisfy F under the same criterion?

Microstate difference. Are some returns non-identical at lower resolution?

Perturbation robustness. Does return survive a declared nontrivial transformation class?

Label invariance. Does return survive arbitrary relabeling of representational tokens?

Orientation dependence. Does reversing orientational roles preserve or destroy return?

Hard-coding test. Does recurrence disappear when explicit cycle templates are removed from the update law?

Coarse-graining test. Can return appear at one resolution while lower-order states do not recur?

Nested return. Can higher- and lower-order identity classes return independently?

Falsification guardrail. If return occurs only because the admissible transition structure explicitly contains the target cycle or a privileged instruction to restore O<sub>F</sub>, return has not been derived.
